# Pseudorandom Number Generators (PRNGs)

Pseudorandom Number Generators (PRNGs) are deterministic algorithms designed to generate sequences of numbers that *appear* random and satisfy various statistical tests for randomness. Unlike True RNGs, they do not rely on unpredictable physical phenomena. Instead, they use a mathematical formula starting from an initial value known as a **seed**.

## How PRNGs Work

1. **The Seed**: A starting number (often provided by a TRNG or the system clock).
2. **The State**: The internal memory the PRNG maintains between number generations.
3. **The Transition Function**: A mathematical operation applied to the current state to produce the next state.
4. **The Output Function**: Extracts the random number from the newly calculated state.

The primary characteristic (and main drawback in cryptographic contexts) of PRNG algorithms is their **determinism**: if the algorithm is initialized with the same seed value, it will generate the exact same sequence of numbers. Furthermore, if an attacker can deduce the internal state of the PRNG, they can predict all future and past generated numbers.

## 1. Classic Algorithms

### Middle-Square Method
Proposed by John von Neumann in 1949, the Middle-Square Method is one of the earliest PRNG algorithms.

**Algorithm:**
1. Take an $n$-digit starting number (seed).
2. Square it to create a $2n$-digit number (pad with leading zeros if necessary).
3. Extract the middle $n$ digits. This is your random number and the seed for the next iteration.

**Example ($n=4$):**
- Seed ($X_0$): `1234`
- Square: $1234^2 = 1522756$. Padded to 8 digits: `01522756`.
- Middle 4 digits ($X_1$): `5227`
- Next generation: $5227^2 = 27321529$.
- Middle 4 digits ($X_2$): `3215`.

**The Flaws:**
The Middle-Square Method is fundamentally flawed for practical use. Its period (the number of generations before the sequence repeats) is usually very short. It frequently gets stuck in short repeating loops, or converges to `0000` (since $0^2 = 0$, it stays at zero forever). Once a generated number repeats an earlier one, the entire sequence from that point will repeat.

### Linear Congruential Generator (LCG)
The LCG is one of the oldest and most famous PRNG algorithms. It is the default algorithm behind `rand()` in C (in many implementations) and the `java.util.Random` class in Java.

**The Formula:**
LCG is defined by the linear recurrence relation:
$$X_{n+1} = (aX_n + c) \pmod m$$

Where:
- $X_n$: The current internal state (or seed $X_0$ initially).
- $m$: The modulus ($m > 0$). Outputs are in the range $[0, m-1]$.
- $a$: The multiplier ($0 < a < m$).
- $c$: The increment ($0 \le c < m$).

#### The Hull-Dobell Theorem
For an LCG to have the maximum possible period (which is $m$, meaning it generates every number from $0$ to $m-1$ exactly once before repeating), the parameters $a, c,$ and $m$ must mathematically satisfy the **Hull-Dobell Theorem**:

1. $c$ and $m$ are relatively prime ($\gcd(c, m) = 1$).
2. $a - 1$ is divisible by all prime factors of $m$.
3. $a - 1$ is divisible by 4 if $m$ is divisible by 4.

#### Common Implementations
- **Java (`java.util.Random`):** $m = 2^{48}$, $a = 25214903917$, $c = 11$ (Outputs bits 47 to 16).
- **C/C++ (`glibc rand()`):** $m = 2^{31}$, $a = 1103515245$, $c = 12345$. 

#### Flaws of LCG
- **State Prediction:** Because LCG just remembers a single state value, solving the linear equation allows predicting future numbers easily.
- **Alternating Bit Problem:** When $m$ is a power of 2, the lower-order bits of the generated sequence have far shorter periods than the higher-order bits (e.g., the lowest bit might strictly alternate 0, 1, 0, 1...).
- **The Marsaglia Effect:** Random numbers generated by an LCG fall entirely onto a small number of predictable parallel planes when plotted in 3D space, meaning they lack true high-dimensional randomness.

## 2. Modern Algorithms

### Mersenne Twister (MT19937)
Developed in 1997, MT19937 is the most widely used general-purpose PRNG today. Its name derives from its massive period length of $2^{19937} - 1$ (a Mersenne prime).

**State Definition:**
MT19937 maintains an internal state array of $n = 624$ integers, each 32 bits wide.

#### Step 1: Initialization
1. Set `MT[0] = seed`.
2. For $i = 1$ to $623$:
$$MT[i] = \left( 1812433253 \times (MT[i-1] \oplus (MT[i-1] \gg 30)) + i \right) \pmod{2^{32}}$$

#### Step 2: The "Twist" (Recurrence Relation)
When 624 numbers are exhausted, a new batch is generated:
$$X_{k+n} = X_{k+m} \oplus \big( (X_k^u \parallel X_{k+1}^l) A \big)$$
Where $A$ is the twist matrix, multiplying by which translates to bitwise XORs.

#### Step 3: Tempering
Before outputting, the number is scrambled ("tempered") to ensure even distribution:
$$y_1 = X \oplus (X \gg 11)$$
$$y_2 = y_1 \oplus \big((y_1 \ll 7) \ \& \ \text{0x9D2C5680}\big)$$
$$y_3 = y_2 \oplus \big((y_2 \ll 15) \ \& \ \text{0xEFC60000}\big)$$
$$Z = y_3 \oplus (y_3 \gg 18)$$

**Flaw:** Because tempering only uses XORs and bit-shifts, it is perfectly invertible. An attacker who observes 624 outputs can reverse these steps to clone the PRNG state.

### Xorshift & PCG Families
- **Xorshift / Xoshiro:** Uses pure XOR and Bit-Shifts. Insanely fast, default in V8 (JavaScript) and Rust.
- **PCG (Permuted Congruential Generator):** Takes a standard LCG and applies a cryptographic permutation to the output, effectively hiding the LCG's flaws and producing high-quality randomness very quickly.

## Pros and Cons

### Pros
- **Blazing Fast:** Standard PRNGs use basic arithmetic/bitwise operations, generating millions of numbers per second.
- **Reproducible:** Providing the same seed guarantees the same random sequence, crucial for debugging simulations, procedural generation in video games (like Minecraft worlds), and unit testing.
- **Uniform Distribution:** Modern PRNGs have incredible statistical properties and massive periods (e.g., $2^{19937}-1$).

### Cons
- **Deterministic:** Completely predictable if the internal state or seed is compromised.
- **Not Cryptographically Secure:** Using LCGs, Mersenne Twister, or Xorshift for generating encryption keys or session tokens is a critical security vulnerability. 
- **Periodicity:** Every PRNG will eventually repeat its sequence (though for MT19937, this takes longer than the lifespan of the universe).
